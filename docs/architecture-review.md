# Qmmp 经典播放器架构评审

评审基线为 `0bead5d`。播放器按应用入口、播放与列表控制（libqmmpui）、音频引擎（libqmmp）和插件分层。播放一首本地歌曲时，MediaPlayer 从列表选择曲目，SoundCore 选择引擎，解码线程读取输入、处理音效并将采样写入 Recycler，OutputWriter 从队列取出采样并送往输出插件。经典界面通过信号显示状态。保留这些边界有利于独立更换解码器、音频设备和皮肤。

## 音频正确性和线程协作

| 优先级 | 基线发现 | 用户影响及修复方向 |
| --- | --- | --- |
| 高 | Qt 输出插件对引擎报告 PCM_FLOAT，隔离设备却收到 s32le。 | 两端对同一组字节的解释不同，浮点输出会失真。统一格式协商，并用非静音信号核验输出。 |
| 高 | 跳转时清空队列并放入一个新块，再归还尚在播放的旧块，新块数量从 1 变成 0。播放字节计数也有加锁重设和无锁累加并存的问题。 | 新位置开头可能丢音，时间和声音可能错位。区分在途块和新队列，由输出线程应用位置变更并维护计数。 |
| 高 | 输出写入失败后直接退出，绕过在途块归还，解码线程可能正在等待队列腾出空间。 | 输出错误应终止本轮播放，唤醒等待线程，允许随后停止或重新播放。基线评审对此项采用静态检查。 |

连续跳转导致缓冲不断缩小的问题已在基线之前修复。评审时三项 CTest 连续三轮通过。原输出回归仅向设备写入 16 位静音并断言容量，无法识别采样格式错误。应同时覆盖格式、信号保真度、在途块交接和设备故障。

## 插件扩展性

解码器是运行时加载的共享库。兼容当前 Qt 和 Qmmp ABI 的插件放入用户配置目录中的 `qmmp/plugins-2.3/Input/` 后，重启即可发现。基线按文件路径去重，却按插件短名保存启用状态；同名的用户版与系统版会造成查询和开关歧义。应规定同名选择顺序，在设置中公开生效文件路径。进程内热重载的优先级较低。

## 性能和界面职责

- 单声道转立体声插件扩容后没有记录临时数组容量，导致每个非空单声道音频块都重新分配。应在相同或更小块之间复用空间。
- 经典主窗口负责组装控件、适配列表、加载歌词及恢复窗口。列表结构变化会重置整个视图并滚向当前曲目，打断浏览。应拆出列表适配并按变化范围通知视图。
- 切歌在界面线程读取并解析歌词，慢盘或网络挂载会拖慢窗口。应在后台读取，按当前曲目接收结果，防止快速切歌时旧歌词覆盖新曲目。
- 皮肤、频谱和窗口磁吸已有独立模块。沿用现有分层，优先处理音频正确性，再改善列表与歌词的响应。

## 本轮修复和验证

- Qt Multimedia 输出使用与引擎一致的采样格式。回归测试将左右声道不等幅、反相的浮点信号送到隔离音频设备，录回并检查幅值和声道关系。
- 用户拖动进度条后，解码线程先切换输出队列，再产生新位置的采样。输出线程负责清空设备缓冲和更新位置计数。队列单测覆盖旧块归还晚于新块入队的情况。另用 MP3 连续跳转 52 次，采样窗口内左右声道的主频保持在 440 Hz 和 720 Hz。
- 写入失败会归还缓冲块、唤醒等待者并报告设备错误。测试在播放中关闭独立 PulseAudio 服务，随后切换输出并重新播放。
- 解码器按短名去重，优先选择可加载的用户插件，设置页可查看生效路径。单声道转立体声处理会复用已经分配的临时数组。
- 播放列表适配和歌词加载已从窗口代码拆出。追加曲目会保留正在浏览的行，歌词在后台读取，快速切歌只显示最新曲目的结果。
- 复核时发现，批量删除不相邻的曲目仍会丢失中间保留曲目的选中状态。适配层现按实际删除和插入的连续区间通知视图。回归用例在播放第 1 首、浏览第 3 首时同时删除第 2 和第 4 首，检查浏览位置仍指向原曲目，播放也继续。
- 普通窗口和迷你横条分别保存布局，小窗保存显示器及工作区内的相对位置。X11 窗口管理器验证中，小窗拖到 `(1168, 80)`，退出后用第二个进程恢复到了相同坐标。原生 Wayland 的顶层窗口定位由桌面合成器决定。

运行 `ctest --test-dir build-classic --output-on-failure` 可复查仓库中的四项回归测试。音频设备断开和浮点回录用例需要 PulseAudio、parec、FFmpeg 以及相应的输入和输出插件。上述音频验证采用软件设备，未测量具体声卡的端到端延迟。
